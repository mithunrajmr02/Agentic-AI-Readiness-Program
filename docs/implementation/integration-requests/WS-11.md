## 1. What WS-11 Implemented & Published

WS-11 owns the Control Tower landing experience (`/tower`) and the Signals triage inbox (`/signals`, `/signals/:id`).

### 1.1 Control Tower Screen (`src/ui/web_react/src/screens/ControlTowerScreen.jsx`)
- **NEEDS YOU Priority Zone**:
  - Highlights active exceptions requiring human review: pending manager approvals (`APR-000012` with quoted §10 threshold rule) and critical telemetry signals (`SIG-000047` config drift, `SIG-000046` overdue PO).
  - Clean victory empty state when all exceptions are handled autonomously (*"Nothing needs you. 4 decisions handled autonomously since 08:00."*).
- **HANDLED WHILE YOU WERE AWAY Proving Zone**:
  - Displays autonomous replenishment executions (`DEC-000123`: Wireless Mouse order under ₹50,000 authority limit) with `<ProvenanceMark kind="computed" />`.
  - Displays principled refusals on insufficient history (`DEC-000124` D4 Colgate refusal) with manual §3 line 35 citation.
- **POSITION SUMMARY Context Zone**:
  - Metric tiles for Open Signals, Pending Approvals, POs in Transit, Total Inventory Value (Cost Price valuation).
  - 90-Day Telemetry breakdown chart covering all 7 detector types (`threshold_breach`, `projected_breach`, `po_overdue`, `config_drift`, `supplier_drift`, `capital_drag`, `data_insufficient`).
- **Telemetry Scan On Demand**:
  - Button calling `POST /api/signals/scan` with React Query mutation and cache invalidation across `signals`, `tower`, and `dashboard`.
- **Demonstration Data Disclosure**:
  - Persistent disclosure banner per 07-UX §5.1 / C8 §7.

### 1.2 Signals Screen (`src/ui/web_react/src/screens/SignalsScreen.jsx`)
- **Signals Inbox Table**:
  - Accessible `<SeverityDot>` (shape + text label, never colour alone).
  - Detector type tags, product context, sufficiency rating badges, detected timestamps, and status badges.
  - Linked decisions (`DEC-... ↗`) for resolved signals.
  - Row click navigation to addressable signal detail `/signals/:signalId`.
- **Filter Bar & Quick Chips**:
  - Filter by search keyword, status (`all`, `open`, `resolved`), severity (`critical`, `high`, `medium`, `low`), and detector type.
  - Quick triage chips: All Signals, Open Only, Critical & High, Config Drift, Projected Breach, PO Overdue, Data Insufficient.
- **On-Demand Telemetry Scan Action**:
  - Triggers anomaly detection scan across database with feedback.

### 1.3 Signal Detail Screen (`src/ui/web_react/src/screens/SignalDetailScreen.jsx`)
- **Evidence Breakdown**:
  - `<EvidenceBlock>` rendering exact mathematical inputs and step-by-step arithmetic (`reorder_point = (demand × lead_time) + safety_stock`).
  - Verbatim citations into `Inventory Manual §3`, `§6`, `§10`, and `§12`.
- **Bounded Agent Narrative**:
  - Marked with `<ProvenanceMark kind="generated" />` and `--agent` left border.
  - Provides interpretive causal hypotheses bounded strictly to verified ledger inputs without fabricating numeric values.
- **Refusal Support (D4 Demo)**:
  - Renders `<RefusalCard>` for `data_insufficient` signals (Colgate) with exact requirements (14 events / 21 distinct days) and actionable next steps.
- **Dual Decision Presentation (D2 Demo)**:
  - Demonstrates split authority on one signal: autonomous order execution (`DEC-000126` ₹40,800) + escalated ROP change (`DEC-000127` / `APR-000013`).
- **Signal Dismissal Workflow**:
  - Modal with recorded dismissal rationale calling `POST /api/signals/:id/dismiss`.
