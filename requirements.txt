# Version policy: every entry carries a verified floor and a major-version

# bcrypt is capped below 5.0 on purpose. Under bcrypt 5.0.0 passlib 1.7.4's
# bcrypt backend is broken outright: hashing any password, even a 7-byte one,
# raises "ValueError: password cannot be longer than 72 bytes". With bcrypt 4.3.0
# the same call succeeds and round-trips. Measured, both ways.
#
# Note this cap does NOT silence the
#   "(trapped) error reading bcrypt version"
# traceback on the first hash call -- that comes from passlib probing
# `bcrypt.__about__.__version__` (passlib/handlers/bcrypt.py:620), an attribute
# bcrypt dropped back in the 4.1 line, so it appears for any bcrypt >= 4.1 and
# would need passlib itself to be replaced. It is cosmetic.
#
# Either way real password hashing is unaffected: the CryptContext in
# src/backend/routers/auth.py lists pbkdf2_sha256 FIRST, so every password this
# app stores uses pbkdf2_sha256 and never reaches the bcrypt backend. The cap
# exists so the declared bcrypt scheme stays usable for verifying a pre-existing
# bcrypt hash rather than being dead weight.
bcrypt>=4.0.1,<5.0.0
